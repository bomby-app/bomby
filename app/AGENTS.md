# Desktop app

Tauri v2: a React frontend in `src/` and a Rust core in `src-tauri/`. `just app` lists its commands. How Tauri fits together is in [docs/tauri-notes.md](../docs/tauri-notes.md), the frontend stack in [docs/frontend-notes.md](../docs/frontend-notes.md).

## Layout

```
index.html, settings.html   one page per window; each loads src/windows/<window>/entry.tsx
public/boot.js              runs before first paint in every window: platform, theme
src/
  index.css                 Tailwind, theme tokens (light and dark), native defaults
  windows/                  one folder per window; mount.tsx wraps every window in the shared providers
    main/                   the main window: sidebar, header, main panel, the command palette (⌘K) and its shortcuts
    settings/               the settings window; sections.ts lists its sections
  features/<feature>/       one folder per feature: theme, call-server (Settings, Call server: LiveKit on this Mac or the user's Cloud, and the page-wide store of which keys are saved), projects, call, agents (finding and setting up the coding agents, and the keys an agent asks for, on its row; fix-steps: the (i) beside a status that opens how to fix it), setup, intro (Settings, Bomby: what Bomby calls the user, and its tone), voice (Settings, Voice: the provider, its key, options and voice), memory (Settings, Memory: remembering the user across calls, with Zep; the call's card when Bomby can't reach it), onboarding (the first-run splash), tray (the menu bar icon's bridge to the call), notifications (finished tasks), about (the version, updates, links and Export diagnostics, whose state is a page-wide store in use-diagnostics.ts; the Dock icon renders from `scripts/export-about-icon.sh`), workspace (the panels beside a project, each opened from its header toggle: its folder's git changes, files and terminals, and the panels extensions add), extensions (Settings, Extensions, with Connect for the hosted MCP ones, Zapier and Composio, and their logos; Project settings' Extensions card; answering Bomby's extension tools over LiveKit RPC while a call is on), todos (a project's to-dos: the To-dos panel, the core's commands and what Bomby's to-do tools ask), call-names (what Bomby's `name_call` asks; the name itself and renaming it are the call feature's), agent-streams (the Agents panel: what each coding agent is doing on the call, live from the core, `streams.ts` its pure reducer), search (the core's search of projects and conversations, for the command palette)
  components/               shared components of our own (choice-list for a card of choices whose chosen row opens its settings, beta-badge for the Beta badge after the wordmark, experimental-badge for what's still settling (a voice provider, an extension, memory), api-key-form, info-tip, app-logo, wordmark, mascot, mascot-card, titlebar-spacer, markdown (what a model or an agent wrote, drawn as it streams, with images left out: every place that shows such text uses it), inline-link, inline-edit-input, error-card, error-toast (an error as a Sonner toast, where a card has no room), copy-command (a Terminal command in a code box with a copy button), shortcut-keys (a `lib/shortcuts.ts` shortcut as Kbd keys), status-row and check-again-button for settings checklists, day-glow and film-grain for the splash and projects backdrop)
  components/ui/            shadcn components, from shadcn's registry
  components/agents-ui/     LiveKit Agents UI components, from LiveKit's registry
  generated/                TypeScript types generated from the core's structs by ts-rs (`just app types`); don't edit
  hooks/, lib/              shared hooks and helpers (lib/cn.ts: cn() with Bomby's own theme names, which lib/utils.ts re-exports; lib/store.ts: page-wide stores that mirror the core; lib/settings-navigation.ts: going to a settings section; lib/shortcuts.ts: keyboard shortcuts; lib/log.ts: log(), a line in `app.log` for what only the page sees; lib/text.ts: text for display, a path's folder name and "a, b and c" lists; lib/chars.ts: text lengths as the core counts them, which a field's limit uses instead of `maxLength` (an emoji is one character, not two); hooks/use-core-event.ts: follow a core event while mounted; hooks/use-dark-mode.ts: whether the page is dark, for libraries that take a theme; hooks/use-mobile.ts and hooks/agents-ui/ come with shadcn's sidebar and Agents UI)
src-tauri/src/              the Rust core: lib.rs (wiring), db.rs (SQLite, migrations), projects.rs, calls.rs (calls, their sessions, transcripts and names), settings.rs, voice.rs (the voice providers from the agent's catalogue, and the user's picks), agents.rs (finding the agents), setup.rs (probing their setup), agent_checks.rs (ready checks remembered across launches), agent_picks.rs (the model and effort the user picked for each agent), adapters.rs (installing ACP adapters), agent.rs (the worker), agent_streams.rs (the Agents panel's live streams: the worker's socket, the call's turns held in memory until it ends, and the page's channel), local_socket.rs (the private folder and per-run secret the worker's sockets share), local_server.rs (the LiveKit server on this Mac), call_server.rs (which LiveKit server calls use), credentials.rs (the keys, a coding agent's included, and every secret held this run for redaction), windows.rs, tray.rs (the menu bar icon), notifications.rs, updates.rs (the version and updates), diagnostics.rs (Export diagnostics: every log, with known keys and key or token shapes redacted, in one zip on the Desktop, one export at a time), search.rs (searching projects and conversations, for the command palette), dev.rs (`just app dev`'s switches for trying states this Mac isn't in; debug builds only), process.rs (waiting on and stopping child programs), workspace/ (the workspace panel: folder checks, git changes, files, the folder watch and terminals), extensions/ (extensions on or off, in Settings and per project, what a call takes of them, and each one's data: todos.rs, and call_names.rs, which only hands Bomby a call's name; the hosted MCP ones' sign-in: oauth.rs for the flow, connections.rs for the grants and commands, tokens.rs for the worker's token socket), sync.rs (locks that outlive a panic, and `Exclusive`, the database's and the keychain's, which a thread can't take twice: docs/decisions/locks-that-cant-be-taken-twice.md), testing.rs (a mock app with an in-memory database and keys, for tests that run a command), app_log.rs, error.rs
src-tauri/voice-providers.json the agent's voice providers, their voices and options, generated from agent/voice_providers/ by `just agent providers`; don't edit
src-tauri/extensions.json   the agent's extensions, generated from agent/extensions/ by `just agent extensions`; don't edit
src-tauri/icons/tray/       the menu bar templates, one per mascot state
src-tauri/capabilities/     what each window may call: main.json, settings.json
src-tauri/Entitlements.plist what signed builds may use under hardened runtime: the mic (docs/releasing.md)
src-tauri/Info.plist        merged into the bundle's: the mic prompt's text and the icon name
src-tauri/permissions/      generated by the build from COMMANDS in build.rs; don't edit
src-tauri/tauri.release.conf.json what release builds add: the signed update bundle
```

## Conventions

- **A feature owns its folder.** Its components, hooks, state and core calls live in `features/<feature>/`. Other code imports what it exports; features don't reach into each other's files. Windows compose features.
- **A window owns its layout.** A new window gets a page (`<name>.html`), `src/windows/<name>/entry.tsx`, an input in `vite.config.ts`, a builder in `src-tauri/src/windows.rs`, and a capability file.
- **Settings grow by sections.** A feature exports a `<Feature>Settings` component; one entry in `windows/settings/sections.ts` (id, label, lucide icon, component) adds it to the sidebar. A section sends the user to another, and to a field there, with `useSettingsNavigation().go({ section, field })` (`lib/settings-navigation.ts`).
- **LiveKit first for calls.** Anything in a call (session, transcript, controls, visualizers, devices) uses LiveKit Agents UI and `@livekit/components-react`, following LiveKit's agent starter (`livekit-examples/agent-starter-react`). Check what LiveKit ships before building anything, and brand it from outside: props, `className`, and `data-slot` styles in `index.css` (the `.call-transcript` rules style `AgentChatTranscript` that way).
- **shadcn first.** Need a button, menu or dialog? Use shadcn's, then build ours on top.
- **Colors come from tokens.** Use the semantic classes (`bg-background`, `text-muted-foreground`, `bg-sidebar`); new colors become variables in `index.css` with light and dark values. No raw hex in components.
- **Native feel.** OS font, arrow cursor, chrome not selectable (opt in with `select-text`), tooltips after a delay, drag regions on bars. A field shows focus with its border alone, never a ring: a global rule in `index.css` takes the rings off every input, text area, select and input group (owner, 2026-11-09). The macOS overlay title bar sets the height of the top rows: use `h-titlebar`.
- **Brand.** Colours, type, logo rules and UI copy follow [docs/brand.md](../docs/brand.md). The mark is `components/app-logo.tsx`, the wordmark `components/wordmark.tsx`, the Beta badge `components/beta-badge.tsx`; nothing else draws them. Copy follows the voice table there ("Add a folder and start talking.", not "No projects found"). Bubblegum (`bg-claude`, `Button variant="claude"`) only means Claude, an error or resuming (the Resume button, the transcript's session pills); highlighter (`Button variant="highlighter"`) is a dialog's Save. Links inside a sentence are `components/inline-link.tsx`. An error the user sees is `components/error-card.tsx` (the failed mascot, the message's first sentence as its headline), or `components/error-toast.tsx` on a screen with no room for a card (the splash); raw errors go to the log. It's `components/mascot-card.tsx`, which the update card and Settings, Bomby use too, so they look alike.
- **Talk to the core in one place per feature.** `invoke()` calls sit in a small typed module in the feature (`features/voice/api.ts`), not scattered through components. Types for what the core sends come from its structs: derive `ts_rs::TS` on the struct and run `just app types` rather than writing them by hand ([how](../docs/tauri-notes.md#generated-types)). A new command goes in `generate_handler!` (lib.rs) and `COMMANDS` (build.rs), and is granted only to the windows that need it in `src-tauri/capabilities/`.
- **Secrets stay in the core.** The page may send a secret to the core; the core never sends one back.
- **Files and names.** Kebab-case file names (`app-sidebar.tsx`), named exports, `@/` imports across folders, relative imports within one. Vite+ (Oxfmt) formats and orders imports and Tailwind classes: run `just app fmt`. All frontend tooling is configured in `vite.config.ts`.
