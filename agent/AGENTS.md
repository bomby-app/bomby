# Voice agent

A LiveKit Agents worker on a voice model the user picks: Gemini 3.8 Live, OpenAI's GPT-Live or Rime's Prism. It talks with the user, hands work to the coding agents over ACP through one tool, `start_task`, and speaks their result when they finish. `just agent` lists its commands.

## Where things are

- `agent.py`: the entrypoint. `probe.py`: checks whether the agents the app found are set up, for Settings (`acp_client/probe.py`, [decision](../docs/decisions/check-agent-setup-with-an-acp-probe.md)).
- `bundle.py`: the packaged agent's one program, which `just agent freeze` freezes with PyInstaller into `dist/bomby-agent/` for the app to ship. `bomby-agent start` is the worker, `bomby-agent probe` the probe ([decision](../docs/decisions/ship-the-agent-and-adapter-as-sidecars.md)). `dev_env.py`: loads `.env` for runs from source only; the packaged agent gets its keys from the app.
- `voice_providers/`: one definition per voice model (`gemini.py`, `openai.py`, `rime.py`): its name, key, voices and default voice, options (switches like Gemini's `google_search`, choices like GPT-Live's response model), the realtime model and the tools it adds ([decision](../docs/decisions/voice-providers-like-harnesses.md)). One that `delegates` (GPT-Live) has a backend model that reasons and calls the tools, with instructions of its own. They're the app's source too: `catalogue.py` writes what Settings needs of them to `app/src-tauri/voice-providers.json` (`just agent providers`), and `just agent check` fails when that file is out of date.
- `extensions/`: one definition per extension (`todos.py`, `call_names.py`, on `extension.py`), a tool set the user turns on in Settings and per project: its tools, a note for the instructions, and what Settings shows. They keep their data in the app and reach it over LiveKit RPC to the app's page (`bridge.py`); the app sends what each needs at the start of a call. The hosted MCP ones (`zapier.py`, `composio.py`, on `hosted_mcp.py`) are a vendor's MCP server instead: the app signs the user in, and the call gets its access tokens from the core over a local socket (`tokens.py`, [decision](../docs/decisions/hosted-mcp-extensions-with-oauth.md)). `catalogue.py` writes what Settings needs to `app/src-tauri/extensions.json` (`just agent extensions`), checked like the providers' ([decision](../docs/decisions/extensions.md)).
- `harnesses/`: one definition per coding agent. To add one, follow [these steps](../docs/decisions/detect-acp-native-agents.md#adding-an-agent).
- `adapters/`: the ACP adapters for agents without ACP of their own (Claude Code, Codex), pinned in `package.json`. The app installs them on Set up; `just agent install` builds them into `adapters/bin` for console runs ([decision](../docs/decisions/install-adapters-on-setup.md)).
- `acp_client/`: the ACP client and runner every harness shares (sessions, steering, the briefing), and `environment.py`, what a harness is started with, apart so the probe never imports LiveKit (a test checks). A failing harness reaches the voice as one short line (`not_ready`, `stopped`, `no_report` for a turn with no final message, `no_model_picked` for an agent whose harness requires a model pick and has none); the details go to the log.
- `tools/start_task.py`: the voice model's one tool. At the top level, `call.py`: what a call's tools share (the runners and the task board); `task_board.py`: the call's tasks, sent to the app, and stopping one when the user asks from the agents panel (`bomby.tasks.stop`, registered in `agent.py`); `lifeline.py`: stops the worker when the app does; `call_failure.py`: tells the app why, when the voice model's service ends a call (no credits, a dead key); `memory.py`: memory across calls in the user's Zep project, with `tools/recall.py` for recalling mid-call ([notes](../docs/zep-notes.md)).
- `prompts/`: each voice provider's instructions, one per tone the user picks (`gemini/`, `openai/` and `rime/`, each with `sharp.md`, `chatty.md` and `playful.md`), GPT-Live's backend instructions (`openai/backend.md`), and `harness-briefing.md` (what every coding agent is told). `voice_prompt.py` picks the call's provider and tone and adds what the call brings, in the provider's style (Markdown for Gemini, plain sentences for GPT-Live and Rime), `backend_instructions` writes the backend's (empty for a provider that doesn't delegate), and `briefing` in `acp_client/runner.py` adds the project to `harness-briefing.md`; all build their sections with `sections.py`, leaving out the empty ones.
- `project.py`, `call_options.py`: what the app sends with each call, read once from the job's metadata. `job.py`'s `JobMetadata` is its one typed contract (pydantic): a new field is one typed line there.
- `check_frozen.py`: checks a frozen agent runs (`just agent check-frozen`).
- `tests/`: unit tests, with a fake ACP agent.

## Rules

- Python dependencies only through `uv`. PyInstaller is in its own `freeze` group, outside `uv sync`.
- Find bundled files through `__file__`, like `prompts/`; frozen, it points inside the folder. A new data folder also needs `--add-data` in `just agent freeze`.
- A coding agent's output reaches the voice model only as the `start_task` result, never through `session.generate_reply` ([why](../docs/decisions/results-only-as-tool-results.md)).
- The tone prompts (`prompts/<provider>/sharp.md`, `chatty.md`, `playful.md`) are the owner's, separate per provider since each model behaves its own way (owner, 2026-11-06). Each is written in its own tone, since the model talks the way its prompt is written; describe the behaviour and never give lines to say, which get parroted. A provider's three share their sections and rules word for word (a test checks it). Change them only when asked, and show the exact text. How they're written: [Gemini](../docs/gemini-notes.md#prompting), [GPT-Live](../docs/openai-notes.md#prompting), [Rime](../docs/rime-notes.md#prompting).
- Text for the voice model, in its prompt or a tool's result, goes through the call's `Style` (`sections.py`: `section`, `code`, `item`), never hand-written Markdown, so a provider that speaks the style it reads (Rime) gets plain sentences. A new provider picks `MARKDOWN` or `PLAIN` as its `prompt_style`.
- No secret reaches a coding agent: `child_environment` in `acp_client/environment.py` strips the `.env` keys, the app's keys and each harness's `blocked_env`. Block a new secret the same way.
