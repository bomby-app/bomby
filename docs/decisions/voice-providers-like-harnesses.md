# Voice providers like harnesses

Status: accepted, 2026-11-06; options with values and providers that delegate added 2026-11-07

## Context

Bomby talked only through Gemini Live. Rime's Prism is a second speech-to-speech model with a LiveKit plugin ([LiveKit's Prism page](https://docs.livekit.io/agents/models/realtime/rime.md)), and OpenAI's GPT-Live a third, built differently: a full-duplex voice model that hands the reasoning and every tool call to a second model ([LiveKit's GPT-Live page](https://docs.livekit.io/agents/models/realtime/gpt-live.md)). The user brings the key for whichever they pick, as with Gemini ([decision](users-bring-their-own-keys-and-claude.md)). Each LiveKit plugin builds its model differently and brings different extras: Gemini has Google Search on Google's side, and Prism accepts function tools only.

## Decision

- Each voice model is one `VoiceProvider` definition in `agent/voice_providers/` (`gemini.py`, `openai.py`, `rime.py`), listed in `PROVIDERS`, the way harnesses are ([decision](one-tool-for-every-agent.md)). A definition holds its id, its name, the variable its key comes in, its voices and default voice, the voice variable for console runs, its options, the realtime model it builds and the tools it adds.
- The app names the provider for each call, with its voice and options (`provider`, `voice`, `provider_options` in the job's metadata). No provider means Gemini, which every call before the choice used. One Bomby doesn't have fails the call at start.
- **Options are a provider's own**, by id with a default, of two kinds (`Switch` and `Choice` in `agent/voice_providers/provider.py`): a switch is on or off, like Gemini's `google_search` (on); a choice is one of its values, like GPT-Live's `response_model` (`gpt-6-luna`). A choice can follow another one listed before it, which decides the values it has: GPT-Live's `reasoning_effort` has the efforts its response model takes, and one the new model doesn't take is the default again. The app sends what the user set, and the provider fills in the rest and ignores ids it doesn't have, and values a choice doesn't have; a value of the wrong kind fails the call at start. A definition that couldn't resolve (a default it doesn't have, values per leader outside its own, a choice following one that isn't listed before it, an id twice) raises when it's defined, so the core's copy of these rules (`voice.rs`) never meets one. An option adds to the prompt only when the model needs telling; Google Search needs nothing (owner, 2026-11-06). Settings shows them by kind, generically: a switch on its own row, choices side by side (owner, 2026-11-07).
- **Prompts are per provider** (`agent/prompts/<provider>/`), each written for how its model behaves, since we can't know that in advance (owner, 2026-11-06). Gemini keeps its Markdown prompts as they were; Rime's are the same tones in plain sentences, because Prism speaks in the style it reads ([notes](../rime-notes.md#prompting)). A provider's `prompt_style` (`agent/sections.py`) also sets how everything else that reaches the model is written: the sections a call adds, agent ids, and lists like remembered facts in the prompt. A tool's results are for the model that calls it, so they follow `tool_style`: the `backend_style` for a provider that delegates (GPT-Live's backend calls `recall_about_user` and the extensions' tools), the `prompt_style` otherwise.
- **The agent's definitions are the one catalogue.** Settings and the splash need each provider's name, key variable, voices and options before any call, so `just agent providers` writes them to `app/src-tauri/voice-providers.json`, which the core embeds. It's committed, so builds never run Python for it, and `just agent check` fails when it's out of date (owner, 2026-11-06). The core keeps only what is the app's: the typed provider ids (a test checks them against the catalogue), the keychain field and setting each pick is saved in, and the copy the page shows (`app/src/features/voice/`, tested against the catalogue too).
- **A provider can delegate** (`delegates`): GPT-Live's voice model talks, and a backend model reasons and calls the tools, with instructions of its own (`agent/prompts/<provider>/backend.md`, then the call's agents and project; `backend_instructions` in `agent/voice_prompt.py`). Its realtime model may be a LiveKit duplex model. Every other provider's backend instructions are empty, so nothing about them changes (owner, 2026-11-07).
- Everything else in a call is shared across providers: `start_task`, steering, memory, resume, the task board.

## Why

- The common shape of a provider shows up only once there are two. A definition per provider keeps each plugin's own settings in one place and leaves the rest of the call untouched.
- Options per provider, rather than one flat list, let a provider bring what only it has without others pretending to.

## Consequences

- **Memory works the same on every provider.** Saving follows LiveKit's own conversation events, which each realtime plugin emits alike (checked for Gemini and Prism: running and final user transcripts with the line's id and start time); only how facts read follows the provider's style. A new provider needs its plugin checked for the same events ([LiveKit notes](../livekit-notes.md)), and nothing else in `agent/memory.py`.
- Adding a provider means a definition, its three tone prompts (and `backend.md` if it delegates), keeping its key from the coding agents (`APP_KEYS` in `agent/acp_client/runner.py`), `just agent providers`, and in the app a `VoiceProvider` variant with its keychain field (`voice.rs`, `credentials.rs`), its copy, logo and key page (`app/src/features/voice/providers.tsx`, `key-pages.ts`), and the key page in both windows' opener allow lists (`app/src-tauri/capabilities/`). Settings and the splash's carousel pick it up from the catalogue; nothing else changes for the providers already there.
- A call that switches provider doesn't change mid-call: like the server, the pick applies from the next call.
