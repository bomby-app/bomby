# Zep notes

Checked 2026-11-06 against `zep-cloud` 4.0.1 (installed source, `agent/.venv/lib/python3.13/site-packages/zep_cloud/`) and Zep's v4 docs (help.getzep.com: adding-messages, users-and-user-graphs, user-summary). Why Bomby uses it: [decision](decisions/memory-across-calls-with-zep.md).

- **4.x addresses users and threads by Zep's UUIDs.** `user.create(user_id=...)` takes our own id and returns a `User` with `uuid_` (`uuid` on the wire); `user.lookup(user_id=...)` finds it again and raises `NotFoundError` when there's none. `thread.create(user_uuid=...)` takes only the user's UUID, so a thread can't be named and looked up by our id: Bomby opens a new thread per call.
- **Search is split by kind**: `graph.search(...)` from 3.x is gone; `graph.search_edges(graph_uuid, query=, page_size=, reranker=, filters=)` returns a pager whose first page is `.items`. A user's UUID works as its graph UUID. Rerankers: `rrf`, `mmr`, `node_distance`, `episode_mentions`, `cross_encoder`.
- **Facts still true**: `EdgeSearchFilters(date_filters=DateFilters(any_of=[DateFilterGroup(all_of=[DateFilter(field="invalid_at", operator="is_null")])]))`. An `Edge` has `fact`, `valid_at` and `invalid_at`.
- **The user's summary** is `user.get_node(user_uuid).summary`, written by Zep from the graph's facts and updated after new data, with a lag. A new user's is a stub made from its id and name, before any facts; real ones quote the id too (Zep's own example: "Emily Painter is a user with account ID Emily0e62 who..."), so Bomby uses a summary only once the graph has facts.
- **The user's name and time zone**: `user.create` and `user.update` take `first_name`, `last_name`, `email` and `time_zone` (IANA). The name maps messages to the user node; without one, Zep can only call the user by their id. `user_id` can't change after creation.
- **Writing**: `thread.add_messages(thread_uuid, messages=[AddMessage(content=, role=, name=, reference_time=)], ignore_roles=["assistant"])`. Zep asks for both sides of every turn as they happen, in the order they were said, with the user's real name and a meaningful assistant name in `name`, and `reference_time` (RFC 3339) as when it was said, which dates the facts. Ignored roles are stored, and give context to replies like "Yes.", but aren't mined for facts. At most 30 messages per call and 4,096 characters per message (400 otherwise). `strict_ontology` stays off, so nothing is dropped for not matching a type.
- **Timeouts and retries**: `AsyncZep(timeout=)` defaults to 60 s per request (`base_client.py`), and each request retries twice on its own (`core/http_client.py`, `base_max_retries`); `request_options={"max_retries": 0}` turns that off per request.
